> * **Обязанность по умолчанию:** после каждой документарной или кодовой правки попытаться обновить актуальные документы непосредственно в «Источниках» **только если доступен соответствующий инструмент записи и права пользователя**; отдельного повторного разрешения на обновление уже согласованных файлов не требовать, когда права предоставлены и содержание однозначно относится к текущей правке.  
> * **Приоритет источников:** редактировать именно Project Knowledge текущего CandySky, не личную Library, не GitHub и не локальную папку вместо него. Внешние хранилища использовать только по отдельному запросу.  
> * **Что обновлять:** technical-spec.md — если изменились требования/статус/архитектура; changelog.md — при каждой правке и принятом решении; instructions.md и project-instructions.txt — при изменении правил; текущий HTML — при изменении кода; readme.md — при изменении структуры/настроек. Формат всегда **полный файл**.  
> * **Подтверждение:** сообщать «Источники проекта обновлены» только после успешного ответа инструмента и проверки содержимого/версии. Иначе сообщать «Обновлены только предоставленные файлы; Источники не изменены» и давать скачиваемые актуальные файлы/ZIP.  
> * **Текущие ограничения (2026-11-11):** в этой сессии **инструмент записи в Project Knowledge недоступен**. Возможность создать вложение, ZIP или изменить файл в личной Library **не даёт** права изменять «Источники». Поэтому документы необходимо заменить пользователю вручную до появления такого доступа. Нельзя обещать автоматическую синхронизацию в будущих чатах.

## **4\. Формат записей в истории**

Для новой записи использовать такой шаблон:  
\#\# YYYY-MM-DD — Rapier Lab X.Y\[.Z\] / DOCS rev N — \<короткое название\>  
\- \*\*Статус:\*\* реализовано / проверяется / запланировано / отменено / документы.  
\- \*\*Задача/основание:\*\* запрос пользователя или обнаруженный дефект.  
\- \*\*Сделано:\*\* конкретные функции, логика, интерфейс.  
\- \*\*Изменено:\*\* чем отличается от предыдущей версии.  
\- \*\*Убрано / отменено / откат:\*\* что исчезло и почему; «нет» тоже записать.  
\- \*\*Проблемы и причины:\*\* симптомы, причина, последствия, нерешённые пункты.  
\- \*\*Проверки:\*\* тест / среда / результат / что НЕ проверено.  
\- \*\*Файлы:\*\* полный перечень изменённых файлов.  
\- \*\*Риски / следующий шаг:\*\* ...

Исторические записи не переписывать задним числом. Обнаружена ошибка в старой записи — добавить следующую запись **«Уточнение истории»** со ссылкой на прежнюю. Рекомендуется заводить идентификаторы проблем вида 3D-001, решений — ADR-3D-001.

## **5\. Защита от регрессий**

**Инварианты, которые нельзя нарушать без согласования:**

> * Натянутая лента визуально натянута и гибкая; нет «невидимой палки» и синусоидальных самоколебаний.  
> * Оба конца привязанной ленты совпадают с реальными точками крепления.  
> * Провисшая / свободная лента подчиняется собственному весу, сопротивлению воздуха и затуханию.  
> * Каждый шар поднимается самостоятельно; шары сталкиваются и не проходят друг через друга.  
> * Гладкий профиль латекса, размер шара около 30 см, сохранены физические габариты и точки крепления.  
> * Скрытая по умолчанию мобильная панель не перекрывает сцену при закрытии и не сбрасывает композицию при открытии.  
> * Ограниченный объём: **5 × 5 × 2,5 м**; сенсорное управление в iPhone/Safari — критично.  
> * Для версии **1.9** — обязательное автономное исполнение без внешних CDN и работоспособность офлайн после успешной первой загрузки и кеширования.

**Отдельно проверять** натянутую / ослабленную / движущуюся ленту, порывы, переносы, коллизии, панель, мобильные жесты и долгую симуляцию. Один скриншот не подтверждает стабильность в движении.

## **6\. Версионирование и файлы**

> * У 3D-конструктора **свои версии** Rapier Lab 1.2 → 1.3 → … → 1.8 → 1.9. Они не обязаны совпадать с версией основного CandySky.  
> * Следующий выпуск согласован как **1.9**. Мелкие исправления после него можно помечать 1.9.1 и далее, не сбрасывая историю.  
> * Имя HTML и версия в \<title\>, видимом интерфейсе и журнале должны быть согласованы. Исторические файлы не перезаписывать под видом нового выпуска.  
> * Новые имена файлов — нижним регистром, содержательные и неизменные после утверждения; instructions.md, technical-spec.md, changelog.md всегда сохраняют эти имена.  
> * Новая фича **не считается готовой**, пока не пройдены её приёмочные проверки (особенно офлайн и реальный iPhone для 1.9).  
> * check.py основного CandySky **запускать только по прямому запросу пользователя и при наличии полного репозитория**, согласно основному CLAUDE.md. Локальные узкие тесты новой лаборатории разрешены и должны быть описаны в журнале.
